1. Project Overview

Basketball Simulator is a full-stack web application that lets users draft real NBA players, build a fantasy roster, and simulate basketball games with an animated play-by-play gamecast. The application pulls live player data from the balldontlie.io NBA API, generates player ratings, and runs a statistical game simulation engine on the server.

Core User Flow

Register / Login → Select Conference & League → Draft 5–12 Players → Pick Opponent Team → Simulate Game → Watch Animated GameCast → View W/L Record

5. Backend — Code Walkthrough

5.1 server/server.js — Entry Point

The main file bootstraps the application:

  • Loads environment variables with dotenv
  • Connects to MongoDB via Mongoose
  • Registers middleware: cors() and express.json()
  • Mounts all route modules under /api/* prefixes
  • Listens on port 5001 (configurable via PORT env var)

5.2 server/models/User.js — User Schema

Defines the Mongoose schema for user accounts. Key fields:

FieldTypePurpose
usernameString (unique)Login identifier
passwordStringBcrypt-hashed password (12 salt rounds)
team.nameStringUser's custom team name
team.players[]ArrayDrafted roster (playerId, name, position, rating, stats)
conferenceString"East" or "West"
leagueString"NBA", "G-League", or "EuroLeague"
draftCompletedBooleanGates access to the game page
wins / lossesNumberRunning game record
gamesPlayed[]ObjectId refsReferences to Game documents

A pre('save') hook hashes passwords before persistence. The toJSON() method strips the password from API responses.

5.3 server/models/Game.js — Game Schema

Stores completed game results: team names, final scores, and the full play-by-play history array. Timestamped automatically.

5.4 server/middleware/auth.js — JWT Middleware

Extracts the Bearer token from the Authorization header, verifies it with jsonwebtoken, and attaches req.userId for downstream route handlers. Returns 401 on missing or invalid tokens.

5.5 server/routes/auth.js — Authentication Routes

EndpointMethodBehavior
/api/auth/registerPOSTCreates user, hashes password, returns JWT + user object
/api/auth/loginPOSTValidates credentials, resets roster/draft/record for fresh start, returns JWT
/api/auth/meGETReturns current user data (protected by auth middleware)

Design choice: Login resets the user's draft and roster every time, so each session is a fresh experience — users pick a new conference, draft a new team, and play a new season.

5.6 server/routes/draft.js — Draft Routes

EndpointMethodBehavior
/api/draft/setupPOSTSaves conference & league selection to the user document
/api/draft/poolGETFetches 100 players from balldontlie, filters by conference, generates ratings
/api/draft/pickPOSTAdds a player to the user's roster (max 12, no duplicates)
/api/draft/completePOSTMarks draft as done (requires minimum 5 players)

The pool endpoint fetches all NBA teams to determine conference membership, then fetches players and filters to only those on teams in the selected conference. It tries to use the paid /season_averages endpoint first; if that returns 401 (free tier), it silently falls back to profile-based ratings.

5.7 server/routes/nba.js — NBA API Proxy

Proxies requests to balldontlie.io, adding the API key. Endpoints:

  • GET /api/nba/teams — All 30 NBA teams
  • GET /api/nba/players — Paginated player search
  • GET /api/nba/players/:id/stats — Season averages for one player (falls back to profile rating on free tier)
  • GET /api/nba/roster — Full team roster with ratings

5.8 server/routes/simulate.js — Simulation Route

Accepts the user's team and opponent roster, runs the simulation engine, saves the result as a Game document, updates the user's W/L record, and returns the full result (scores, plays, box scores).

5.9 server/services/playerRating.js — Rating System

Contains two rating algorithms:

  • calculateRating(stats) — Stats-based rating (40–99 scale). Requires season averages data. Weights: Scoring (max 35), Efficiency (max 20), Playmaking (max 15), Rebounding (max 10), Defense (max 10), Turnover penalty (max −5). Base floor of 40 for any NBA player.
  • calculateRatingFromProfile(player) — Profile-based heuristic for the free API tier. Uses draft round, pick number, and years of experience to generate ratings. First-round lottery picks start at 72–88; undrafted players start at 55–67. Veterans get a bonus, players 14+ years decline slightly.

5.10 server/services/simulation.js — Game Engine

The core simulation engine models a full basketball game:

  • 4 quarters × 12 minutes (720 seconds each), with possessions consuming 5–24 seconds
  • Weighted player selection: Higher-rated players get more touches via pickWeightedPlayer()
  • Shot outcomes are probability-based: shot chance = 35% + (rating/99 × 25%), yielding 35–60% for any player
  • Play types: 2-pointers, 3-pointers, free throws, missed shots with rebounds, assisted baskets, turnovers
  • Overtime: If tied after 4 quarters, 5-minute OT periods repeat until a winner emerges
  • Output: Returns team names, final scores, full play-by-play array (with quarter, clock, team, text, running scores), and player box scores (pts, reb, ast)

6. Frontend — Code Walkthrough

6.1 client/src/App.jsx — Routing & Navigation

Uses React Router v6 to define three routes:

PathComponentGuard
/loginLoginPageRedirects to /draft if already logged in
/draftDraftPageProtectedRoute (requires auth token)
/gameGamePageProtectedRoute + DraftGate (requires completed draft)

A persistent nav bar shows the app name, username, W/L record, and a logout button. The DraftGate component redirects users to /draft if they haven't finished drafting.

6.2 client/src/context/AuthContext.jsx — Auth State Management

React Context provider that manages:

  • token — JWT stored in localStorage for persistence across page reloads
  • user — Full user object fetched from GET /api/auth/me on mount
  • login(token, user) — Saves token and sets state
  • logout() — Clears localStorage and resets state
  • loading — Prevents flash of login page before token validation completes

6.3 client/src/pages/LoginPage.jsx — Authentication UI

A toggle form that switches between login and registration modes. Dark-themed card layout with orange accent branding. Calls POST /api/auth/login or POST /api/auth/register and passes the response to AuthContext.login().

6.4 client/src/pages/DraftPage.jsx — Conference Selection & Draft

Two-phase page:

  1. Setup Phase: Displays buttons for league selection (NBA, G-League, EuroLeague) and conference (Eastern/Western). Saves selection via POST /api/draft/setup.
  2. Draft Phase: Two-panel layout — left panel shows the available player pool (100 players filtered by conference, sorted by rating), right panel shows the user's growing roster. Each player card displays name, position, team, and rating badge. Draft button adds player to roster. "Complete Draft" button appears once minimum 5 players are picked.

6.5 client/src/pages/GamePage.jsx — Game Day

Displays the user's starting five, a grid of 30 NBA teams as selectable opponents, and the selected opponent's roster preview. Clicking "Simulate Game" sends both rosters to POST /api/simulate and passes the result to the GameCast component.

6.6 client/src/components/GameCast.jsx — Animated Play-by-Play

The centerpiece visual component. Features:

  • Live Scoreboard: Shows team names, running scores, current quarter, and game clock
  • Play Stream: Plays appear one by one with a CSS fadeSlideIn animation
  • Speed Controls: Slow (1200ms), Normal (800ms), Fast (400ms), Turbo (100ms)
  • Playback Controls: Play/Pause toggle, Skip to End button
  • Auto-scroll: The play log auto-scrolls to keep the latest play visible

Uses setInterval with a ref for the timer, advancing currentIndex through the plays array at the selected speed.

8. How to Run Locally

Prerequisites

  • Node.js 18 or higher
  • MongoDB Community Server (or a MongoDB Atlas connection string)
  • A paid API key from app.balldontlie.io

Step 1 — Clone & Install

git clone https://github.com/zahyaa/NBASIM_Project_Full.git
cd NBASIM_Project_Full

# Install backend dependencies
cd server
npm install

# Install frontend dependencies
cd ../client
npm install

Step 2 — Start MongoDB

# macOS (Homebrew)
brew services start mongodb/brew/mongodb-community

# Linux (systemd)
sudo systemctl start mongod

# Or use MongoDB Atlas and set the connection string in .env

Step 3 — Configure Environment

cd server
cp .env.example .env

Edit .env with your values:

MONGODB_URI=mongodb://localhost:27017/nbasim
JWT_SECRET=your-secret-key-here
BALLDONTLIE_API_KEY=your-api-key-here

Step 4 — Start the Backend

cd server
node server.js

Server starts on http://localhost:5001

Step 5 — Start the Frontend

cd client
NODE_OPTIONS=--openssl-legacy-provider npm start

React dev server starts on http://localhost:3000 and proxies API calls to port 5001.

Important Notes

  • Port 5001: macOS AirPlay Receiver occupies port 5000. This project uses 5001 instead.
  • OpenSSL flag: NODE_OPTIONS=--openssl-legacy-provider is required because react-scripts 3.x uses a legacy Webpack version incompatible with Node 18+'s OpenSSL 3.

9. How to Deploy to Production

Option A — Render (Recommended for simplicity)

  1. Push code to GitHub (already done at github.com/zahyaa/NBASIM_Project_Full)
  2. Backend: Create a "Web Service" on render.com
    • Root directory: server
    • Build command: npm install
    • Start command: node server.js
    • Set environment variables: MONGODB_URI, JWT_SECRET, BALLDONTLIE_API_KEY, PORT=5001
  3. Frontend: Create a "Static Site" on Render
    • Root directory: client
    • Build command: NODE_OPTIONS=--openssl-legacy-provider npm run build
    • Publish directory: client/build
    • Add rewrite rule: /* → /index.html (for React Router)
  4. Update the frontend's API base URL to point to the backend's Render URL (or set up a proxy)

Option B — Heroku

  1. Add a root Procfile: web: node server/server.js
  2. Serve the React build from Express by adding static file middleware: 
    app.use(express.static(path.join(__dirname, '../client/build')));
app.get('*', (req, res) => {
  res.sendFile(path.join(__dirname, '../client/build/index.html'));
});
  3. Build the client: cd client && NODE_OPTIONS=--openssl-legacy-provider npm run build
  4. Set environment variables via Heroku dashboard or CLI
  5. Deploy: git push heroku main

Option C — VPS (DigitalOcean, AWS EC2, etc.)

  1. Install Node.js and MongoDB on the server
  2. Clone the repo, install dependencies, build the client
  3. Use pm2 to run the server as a daemon: pm2 start server/server.js --name basketball-sim
  4. Use Nginx as a reverse proxy: 
    server {
    listen 80;
    server_name yourdomain.com;

    location /api/ {
        proxy_pass http://localhost:5001;
    }
    location / {
        root /path/to/client/build;
        try_files $uri /index.html;
    }
}
  5. Enable HTTPS with Let's Encrypt / Certbot

Database (Production)

Use MongoDB Atlas for a managed cloud database:

  1. Create a free cluster at cloud.mongodb.com
  2. Create a database user and whitelist your server's IP (or allow 0.0.0.0/0)
  3. Copy the connection string and set it as MONGODB_URI
